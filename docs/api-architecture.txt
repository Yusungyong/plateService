API 구조 관리

진입: /admin/api-registry (운영 메뉴 > API 구조 관리).
지정된 운영 계정 su12ng만 사용한다. 다른 최고 관리자도 이 화면은 열 수 없다.
서버는 검증된 JWT subject와 DASHBOARD_READ 관리자 권한을 함께 확인하며 결과를 private,no-store로 반환한다.
웹의 메뉴/직접 경로 역시 JWT subject를 사용한다. 이름·이메일·캐시된 사용자 정보는 접근 근거가 아니다.
다른 운영자의 기존 대시보드·업무 메뉴 권한은 유지한다.

탐색
- 메뉴 관계: 처음에는 연결된 홈 메뉴(없으면 첫 연결 메뉴)의 관계도를 보여준다. 메뉴/업무/API 버튼에 이동·상세 동작을 표시하고 통계·선택 메뉴·안내는 일반 정보로 구분한다.
- 모바일에서는 긴 메뉴 목록 대신 같은 선택을 적용하는 드롭다운을 사용한다. 필터 결과가 없더라도 현재 선택한 메뉴와 연결 API 없음 상태를 유지한다.
- 검색·사용 영역은 메뉴 관계 탭에서 사용한다. 업무·HTTP는 상세 필터를 펼쳐 사용한다. 서비스 구조 탭에는 그림에 적용되지 않는 API 필터를 표시하지 않는다.
- API 상세는 관계도 바로 아래, 목록 위에 나타난다. 함께 사용하는 메뉴로 이동할 수 있고 소스·서버 형식은 필요할 때 펼친다.
- API 목록은 업무/API/사용 메뉴를 기본으로 표시한다. 호출 지표 보기를 누르면 호출 수·오류율·평균 응답·상태와 관측 범위 설명이 표시된다. JSON 내보내기는 조회한 보호 snapshot의 전체 분석 자료를 저장한다.
- 모듈 구조: 업무 선택 드롭다운과 기존 업무 연결 그림으로 서비스 생성자의 모듈 간 포트 의존성을 살펴본다. 근거 및 서비스 인터페이스 목록은 기본 접힘. 실제 호출 trace가 아니다.
- 공통화 현황 보기: 좋아요 재사용 사례, 호환 기반·모듈 분리의 완료 및 DTO/Entity·저장 통합·구 API 폐기의 후속 범위를 펼쳐 확인한다.

자료 해석
API는 HTTP method+path로 중복을 제거한다. 여러 메뉴에서 사용하는 API는 메뉴 연결마다 표시되지만 전체 API 수에는 한 번만 포함된다.
연결 근거 없는 API나 미관측 API를 숨기거나 폐기 대상으로 판단하지 않는다.
메뉴 관계는 소스 분석 및 선정 공통 API에 대한 최신 앱 연결 보정이다. 서버 timer는 API method/path/status 단위이며 메뉴별 실제 호출로 나눌 근거가 없다.
호출·오류·평균 응답 지표는 현재 서버 프로세스의 누적 관측이다. p95·마지막 호출 시각·장기 이력은 제공하지 않는다.
구조 snapshot은 게시된 76개 호환 포트 구현과 공통 좋아요 사용 사례의 컴파일된 생성자 → 모듈 인터페이스 의존성을 분석한다.
저장소·DTO 타입 참조·동적 호출·setter/ObjectProvider 주입 등은 전체 dependency graph로 주장하지 않는다. 서비스 포트가 있어도 저장 DTO의 내부화 완료를 뜻하지 않는다.

앱 영향
이번 화면 단순화는 웹 UI만 변경한다. 앱 API 계약과 Android/iOS 빌드, 서버 응답 및 지정 운영자 접근 제한은 기존대로 유지한다.

2026-10-12 — 최신 기능·최적화 연결

운영 > API 구조 관리 > 기능·최적화에서 추가 기능 10개, 최적화 근거 8개를 확인한다.
홈 대화·약속 바로가기, 콘텐츠·식당 후보 공유, 주변 식당 비교, 공유 장소 지도,
기존 공유함·약속, 1:1 함께 보기·입력 상태, 그룹 초대·대화, 사진·음성 전송,
확장 보드·반응, 댓글 언급을 기존·신규 API에 연결한다.
프로필 썸네일·캐시, 대화 요청·메모리 제한, 읽음·알림 카테고리, 좋아요 명시 상태,
댓글 공통 처리, 홈 갱신·후보 묶음, DB 인덱스·쿼리, 공통 소스 정리가 최적화 항목이다.

관리 데이터:
- src/admin/api/apiRegistryConsumers.json: 81개 검토된 호출 계약과 최신 메뉴 근거.
- src/admin/api/apiRegistryUpdates.json: 기능·최적화 설명, 연결 계약, 검토일·확인 사항.
- src/admin/pages/apiRegistryUpdates.js: 연결 집계·상태 설명·소스 주석.
추가 HTTP 호출 없이 기존 GET /api/admin/api-registry 응답에 검토 자료를 결합한다.
메뉴 관계는 기본적으로 합집합이다. 구형 좋아요 UI 연결 제거만 linkPolicy=replace로 명시한다.
서버의 경로·모듈·권한·ID·매핑을 소스 메타데이터로 덮어쓰지 않는다.
서버와 앱의 {id}/{roomId} 같은 변수명 차이는 같은 API로 정규화해 집계한다.
서버 호출 지표는 경로별로 한 번 분류하고, 미관측 값은 null을 유지한다.

서버 등록 상태:
- activeRoutes에 있는 계약만 '서버 등록 확인'으로 집계한다.
- 클라이언트 소스에만 있는 계약도 목록·그림에 표시하되 등록 API 수에 포함하지 않는다.
- 신규 홈·DIRECT 실시간 계약 8개는 서버 PR #149 기록에 연결한다.
- 그룹·미디어·스마트 보드의 클라이언트 계약 17개는 서버 Issue #147 구현 대기다.
- 범용 live/{scope} 템플릿을 별도 구현된 API로 중복 집계하지 않는다.
- API 등록은 기능 활성화, capabilities 지원, 앱 배포, 성능 측정의 증거가 아니다.
등록 수는 실시간 서버 응답을 사용한다. DB V45·썸네일 V47 등은 적용 기록으로 설명하고,
운영 p95·체감 성능·푸시 전달 성공을 추정하거나 숫자로 만들어 표시하지 않는다.
서버 PR #134·웹 PR #37의 공통 소스 정리는 별도 변경이며 이 브랜치에서 병합하지 않는다.

연결 API 보기로 목록과 관계도를 함께 좁힐 수 있다. API 상세에 관련 근거를 표시하고,
JSON 내보내기에 업데이트 카탈로그·집계·기존 서버 지표·오류 보고를 포함한다.
미등록 상태는 지표를 펼치지 않아도 보인다. 오류 우선 강조·자동 새로고침·권한 실패 시
민감 스냅샷 제거와 su12ng + DASHBOARD_READ 접근 제한은 유지한다.

검증:
전체 웹 테스트 29 suites / 247 tests, 공개 약관 13 tests, production build 통과.
새 검증은 소스/서버 병합, 변수명 정규화, 미등록 집계, 오류 강조, 탭 키보드 이동,
권한 실패 시 새 탭 제거, JSON 내보내기, 기존 접근 제한을 포함한다.
앱 검토 소스 해시는 스냅샷 시점의 근거다. 앱 또는 API 계약 변경 시 메뉴/계약/설명과
해시를 함께 갱신하고 검증해야 한다. 이 문서의 빌드 통과는 운영 배포 완료를 뜻하지 않는다.
