# 운영 지표에서 근거와 조치까지

사용자가 지표를 보고 다음 행동을 바로 선택할 수 있도록 13개 메뉴를 연결했다. 숫자 클릭은 조회만 수행하고, 저장·숨김·세션 종료 등 조치는 별도 확인을 유지한다.

| 메뉴 | 지표에서 이어지는 흐름 |
| --- | --- |
| 회원 모니터링 | 회원 수·가입·활성·권한 변경·위험 수 → 같은 집계 조건의 페이지 목록 → 회원 상세 → 원래 근거로 복귀. 로그인 실패율 → 실제 성공·실패·기타 건수 그래프 |
| 대시보드 | 승인 대기·신규 신청 → 조건 목록. 날짜 막대 → 일별 근거와 해당 사진. 지역 → 지역·기간 사진 목록. 이전 조회 결과는 마지막 성공 기간에 연결 |
| 사진 피드 | 서버 전체 신고/추천 필터, 정확한 작성자·등록일·지역 조건, 선택한 사진·페이지 유지. 조치 중 이탈과 다른 대상 응답 덮어쓰기 방지 |
| 제철 음식 | 전체·공개·초안·보관 수 → 해당 목록. 조건 초기화·뒤로 가기·0건 안내, 편집 폐기 승인 후 초안 제거 |
| 입점 신청 | 상태·기간·지역 등 → 서버 조건 목록, 선택 조건과 개별 해제, 목록 포커스 |
| 매장 관리 | 노출 상태·메뉴 수 → 해당 목록·매장 메뉴. 상세에서 검증한 내부 returnTo로 복귀 |
| Q&A | 문의 상태 → 동일 조건 목록·답변. 목록 복귀 및 미저장 보호 |
| FAQ | 공개 상태·분류 → 목록. 조회 수와 노출 순서는 제공되는 집계 의미를 설명 |
| 운영 홈 | 서버 실패·응답 지표 → 실제 상태별 요청 근거, 관련 API·사진 신고로 이동 |
| 장애 진단 | 푸시 상태·전달 단계 → 최근 전달 표본과 선택한 전달의 근거 |
| 배포·품질 | 검증/배포 단계 → 리비전이 일치하는 실행 기록·관련 점검 이력 |
| API 구조 관리 | 등록·미등록·오류 수 → 해당 API 목록. 상태·응답·오류율 → 원본 관측과 오류 근거 |
| 마케팅 | 검토·대기·게시 완료·결과 미확인 → 제작/게시 상태별 목록과 개별 근거. 성과 수치 → 해당 그룹 집계 |

## 집계 범위

- 회원 summary와 새 metric-details는 같은 SQL 조건을 사용한다. 각각 조회한 시점이 다르면 숫자가 바뀔 수 있어 상세의 조회 시각과 합계를 표시한다. 비노출·삭제 계정은 익명 행으로 유지한다.
- 대시보드 전체 신고 수는 사진 외 대상도 포함한다. 사진 신고 목록은 전체 기간 사진만이라는 범위를 밝힌다.
- 변경된 매장은 현재 수정일 기준이다. 매장 관리 화면은 기간 필터를 지원하지 않으므로 전체 기간 링크라고 표시한다.
- 회원 사진의 시간 단위 30일 집계와 목록의 날짜 단위 경계 차이를 안내한다.
- 서버 응답은 현재 프로세스 누적값이다. 저장된 시계열이 없는 지표에 추세 그래프를 만들지 않는다.
- 푸시 전체 집계와 최근 30건 표본, FAQ/Q&A의 불러온 목록 필터 범위를 구분한다. 개인별 성과 명단이나 조회 로그를 만들어내지 않는다.

## 검증 방법

`CI=true npm test -- --watchAll=false --watchman=false --runInBand`

`npm run build`

`scripts/admin-workspace-browser.mjs`와 `scripts/admin-operations-drilldown-browser.mjs`는 localhost에서 모든 API를 합성 응답으로 대체한다. 1440/390/768px에서 클릭·조건·복귀·근거·포커스·가로 넘침을 확인한다. 실제 운영 데이터나 쓰기 요청을 사용하지 않는다.

서버 계약과 실제 PostgreSQL 검증은 plateAppServer #170/#171, PR #172를 참고한다. DB 마이그레이션은 없다. 앱 바이너리 변경도 없다.
