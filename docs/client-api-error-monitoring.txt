앱·웹 API 오류 모니터링 — plateService #28 / plateAppServer #102 / plateApp2 #16

운영 API 구조 관리 화면은 기존과 같이 정확한 username su12ng와 운영 권한을 함께 확인한다.
clientErrors는 기존 GET /api/admin/api-registry 응답의 추가 필드이며 다른 API 계약은 유지한다.
보고 합계, 영향 API, 메뉴·업무·관계도·목록의 오류 표시를 제공한다. HTTP 5xx/연결 실패/시간 초과는
“서버·연결 오류”, HTTP 4xx는 “요청 오류”로 표시하며 색상과 함께 텍스트·기호로 구분한다.
관계도에는 최대 8개 API를 표시하고 오류 심각도와 보고 수를 우선한다. 상세 화면은 유형별 전체 수,
보고한 클라이언트 목록, 최신20개 (유형·HTTP상태·클라이언트) 그룹의 수와 마지막 수신 시각을 표시한다.
최근 그룹 수를 클라이언트별 전체 수로 합산하지 않는다. 실제 호출 순서나 장애 전파 원인을 추정하지 않는다.

집계 범위는 서버 수신 시각의 최근 24개 시간 버킷(현재 버킷 포함)이다. windowStart는 현재 시각을
정시로 내린 값에서 23시간 전, windowEnd는 응답 시각이다. UI는 “최근 24시간 구간”과 시작/끝을
표시한다. 클라이언트 보고에는 전체 요청 수가 없어 오류율을 계산하지 않는다. 기존 서버 프로세스
누적 호출 수·오류율·평균 응답은 별도 선택 표시로 유지한다. 보고 없음은 정상/미사용의 증거가 아니다.
집계 누락, available:false 또는 유효하지 않은 데이터는 “집계 확인 불가”로 표시하고 0으로 대체하지 않는다.

“오류가 보고된 API만”을 켜면 기존 메뉴·검색·영역·업무 필터를 초기화하여 다른 메뉴의 실패도 볼 수 있다.
기본 홈 메뉴 선택과 두 탐색 탭, 접힌 추가 정보, 기본 3열 목록은 유지한다. 자동 새로고침은 기본 30초이며
문서가 보일 때만 시작한다. 끄기, 마지막 확인 시각, 중복 요청 방지, 언마운트 시 중단을 제공한다.

공통 웹 apiClient는 최종 HTTP 400~599, NETWORK_UNAVAILABLE, NETWORK_TIMEOUT만 비동기로 보고한다.
복구된 최초 401, 사용자 취소, 계정 변경 중 오래된 응답은 제외한다. 공유된 토큰 갱신 실패는 실제
POST /api/auth/refresh 경로로 한 번 보고하며 세션을 지우기 전에 기록한다. 성공한 실제 요청은 일시
중단된 보고 큐를 깨우되 기존 재시도 대기 시각을 우회하지 않는다.

별도 raw fetch로 POST /api/monitoring/client-errors에 다음 6개 필드만 전송한다.
{events:[{eventId:UUIDv4,method:GET|POST|PUT|PATCH|DELETE,path:등록된 경로 템플릿,
kind:HTTP|NETWORK|TIMEOUT,status:HTTP인 경우 정수400~599 아니면null,client:WEB}]}
Authorization, 쿠키, 실제 사용자 경로 값, 쿼리, 본문, 오류 메시지, 사용자 식별자와 클라이언트 시각은
전송하지 않는다. 정적 310개 서버 경로 목록에서 리터럴 우선·동일 메서드로 매칭하며 외부 URL, userinfo,
dot segment, 인코딩 구분자, 제어 문자, 역슬래시와 모호한 템플릿을 제외한다. 보고 엔드포인트는 제외하여
재귀 보고를 방지한다. 큐는 메모리 최대100개·TTL24시간, 한 배치20개·요청/JSON 읽기 제한4초이다.
재시도에도 같은 eventId를 사용한다. 인증 없는 서버는 UUID 중복 제거와 수신량 제한을 수행한다.

202 + success:true + data.accepted/data.duplicates의 정수 합이 배치 크기와 같을 때만 전달 완료로 판단한다.
429, 5xx, 연결 실패, 예기치 않은 성공/리다이렉트/잘못된 응답은 초기 전송 후2초·10초·60초로 최대3번
자동 재시도하고 이후 실제 사용자 통신이 올 때까지 멈춘다. 영구4xx(400/413 등)는 해당 배치를 버려
나머지 큐를 막지 않는다. 보고 실패는 사용자 API 요청 완료를 지연하거나 재귀 호출하지 않는다.

서버는 수신 집계와 중복 제거 기록을 최대7일 보관한다. 클라이언트의 이전 배포는 보고를 하지 않아도
호환된다. 새 앱 보고는 해당 앱 버전 설치 이후부터만 들어온다. 집계는 서버 API + 새 웹/앱 연동이며
서버 메트릭, 브라우저 fixture 또는 합성 테스트의 보고를 운영 실제 사용자 보고라고 표시하지 않는다.
