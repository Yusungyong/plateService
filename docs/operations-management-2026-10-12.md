# 접시 운영 관리 · 2026-10-12

## 적용 범위와 상태

React 관리자 웹, Spring Boot 서버와 기존 PostgreSQL에 운영 확인 기능을 추가했다. 기존 API 구조 관리·메뉴 관계도·앱 오류 보고를 재사용한다. 과거 철회한 AI 작업 관리 메뉴는 복원하지 않는다.

이번 변경은 소스 구현·로컬 검증·리뷰용 브랜치 준비 단계다. 운영 배포, 운영 DB V48 적용, GitHub 수집 토큰 등록, 앱 스토어 배포는 수행하지 않았다. 관리자 웹이 사용하는 미배포 서버 기능은 배포 후 사용할 수 있다.

## 사용자 메뉴

su12ng 계정으로 관리자 로그인 → 왼쪽 **서비스 운영**.

| 메뉴 | 주소 | 확인할 수 있는 것 |
| --- | --- | --- |
| 운영 홈 | `/admin/operations` | 앱 API 오류, 서버 응답 실패, FCM 접수 결과, 활성 신고 표시, 느린 서버 응답, 수집 상태 |
| 장애·알림 진단 | `/admin/operations/incidents` | API와 메뉴 관계, 오류 유형·최근 시각, 기존 API 관계도 연결 |
| 푸시 전달 | `/admin/operations/incidents?view=push` | 전송 시도 → FCM 접수 → 앱 수신 콜백 → 알림 열기, 생략 이유 |
| 배포·품질 | `/admin/operations/releases` | 플랫폼·버전·빌드·SHA 등록, GitHub 실행 결과, 실제 기능 점검과 변경 이력 |

읽기는 검증된 JWT subject가 정확히 `su12ng`이고 `DASHBOARD_READ` 권한이 있어야 한다. 기록 변경은 `SETTING_MANAGE`도 필요하다. 다른 관리자, 일반 회원, 익명 사용자, 표시 닉네임을 su12ng로 바꾼 사용자는 접근할 수 없다. 웹 메뉴 제한과 서버 제한을 함께 적용했다. 응답은 `Cache-Control: no-store, private`다.

## 추가 API 계약

모든 운영 API는 기존 `ApiResponse` 형태를 사용한다. 등록은 배포를 실행하지 않는다.

| 메서드 | 경로 | 권한 / 결과 |
| --- | --- | --- |
| GET | `/api/admin/operations/snapshot` | 운영자 읽기 / 지표·진단·버전·수집 범위 |
| GET | `/api/admin/operations/push-attempts/{deliveryId}` | 운영자 읽기 / 최근 24시간의 해당 전송 시도 |
| POST | `/api/admin/operations/releases` | 운영자 쓰기 / `releaseId` |
| POST | `/api/admin/operations/releases/{releaseId}/checks` | 운영자 쓰기 / `recorded` |
| POST | `/api/monitoring/push-receipts` | 로그인한 해당 수신자 / 202 |

버전 등록 body: `{"platform":"ANDROID","version":"2.0.13","build":"32","revision":"실제 40자리 소문자 커밋 SHA"}`. 플랫폼은 ANDROID, IOS, SERVER, WEB. 동일한 플랫폼·버전·빌드·SHA 재등록은 같은 ID를 반환한다.

점검 body: `{"eventId":"요청별 UUID","check":"CHAT","result":"PASS"}`. 항목은 LOGIN, FRIEND_REQUEST, CHAT, CONTENT_SHARE, PUSH, STORE_PUBLISHED, DEVICE_CHECK. 결과는 PASS, FAIL, PENDING. 동일 UUID/내용 재시도는 중복 기록되지 않으며 UUID를 다른 내용으로 재사용하면 409. 버전당 최대 200개 기록, 화면에서는 항목별 최신 결과와 최근 20개 이력을 제공한다.

수신 body: `{"receiptKey":"서버가 해당 전송에 넣은 UUID","state":"RECEIVED"}`. 상태는 RECEIVED 또는 OPENED. 해당 토큰의 현재 계정만 기록하며 탈퇴 중·소유자 불일치·7일 경과·실패 전송은 404. 최초 확인 시각을 유지한다.

기존 엔드포인트는 제거하지 않았다. 서비스 포트는 78 → 79, 선언된 오류 보고 허용 계약은 321 → 326. 신규 HTTP 계약 5개와 연결된 관리자/앱 메뉴를 기존 API 목록에 등록했다. 기존 채팅 확장 계약은 미배포 상태가 유지된다.

## 숫자와 그림의 의미

- 서버 응답 건수·평균·실패율은 현재 서버 프로세스의 메서드·경로·응답 상태별 누적값이다. HTTP 4xx와 5xx를 포함한다. 화면 로딩 시간이나 p95가 아니다.
- 앱 오류는 기존 24 UTC 시간 버킷의 보고 건수다. 영향 사용자 수·버전별 오류율은 아직 수집하지 않는다.
- 푸시는 최근 24시간의 기기 토큰별 전송 시도다. FCM SUCCESS는 제공자의 접수이며 실제 기기 수신과 다르다. 콜백이 없으면 미확인이다. 앱 강제 종료·네트워크 상태 등에 따라 콜백이 누락될 수 있다.
- 활성 신고 표시는 fp_40의 활성 플래그이며 미처리 운영 업무 건수로 해석하지 않는다.
- 메뉴/API 관계는 소스에 확인된 연결이며 요청별 분산 추적 결과가 아니다.
- 백업·활성 사용자·앱 화면 속도는 미연동/미수집으로 명시한다. 비어 있는 기록과 조회 실패를 구별한다.

## 앱 푸시 연결

서버는 기기별 푸시 data에 `plateReceiptKey`를 넣는다. 앱은 포그라운드/백그라운드 수신에 RECEIVED, 알림 탭·초기 알림 진입에 OPENED를 보낸다. 이 부분은 새 앱 빌드가 필요하다. 기존 앱은 계속 푸시를 받을 수 있지만 새 수신 근거는 생성하지 않는다.

앱에는 본문·기기 토큰·수신자·메시지 ID를 새 API로 보내는 코드가 없다. 계정 전환 시 세션 epoch로 차단하고, 동시 20건·중복 확인 100건/5분·최대 3회 재시도로 제한한다. 재시도 큐를 디스크에 저장하지 않는다. 진단 API 실패를 앱 오류 보고에 다시 넣지 않는다.

서버 진단 저장은 독립 트랜잭션으로 수행하며 기존 트랜잭션이 있으면 원래 전송 로그가 커밋된 뒤에 실행한다. 진단 기록 장애가 알림 비즈니스 트랜잭션을 취소하지 않게 했다. SQL 실행·락 대기 시간을 제한한다.

## DB와 롤백

V48 `operations_console`은 수신 확인·전송 생략·버전·점검·워크플로 기록 테이블 5개와 조회 인덱스를 추가한다. 기존 fp_25 전송 로그의 PK를 참조해 삭제를 cascade한다. 회원 탈퇴 스키마 카탈로그와 이전 JAR 호환 패키지 생성 allowlist도 함께 갱신했다. 부분 스키마나 미검토 컬럼은 기존의 fail-closed 삭제 검토 방식을 유지한다.

보관기간: 수신 확인·생략 7일, 버전·점검·워크플로 90일. 정리 작업은 1시간마다 실행된다. 버전 삭제 시 점검도 cascade한다. 기존 fp_25 로그 자체의 기존 보관 정책을 변경하지 않았다.

직접 배포 도구는 호환 롤백 JAR 검증 후 Flyway target을 48로 올리도록 준비했다. V48 이후 단순히 이전 JAR로 교체하면 기존 삭제 카탈로그가 신규 테이블을 거부하므로 호환 JAR을 사용해야 한다. 현재 main은 V47이며 미게시 그룹/미디어 서버 기능이 과거 V48 번호를 쓰던 임시 소스와 혼동하면 안 된다. 해당 후속 기능을 재개할 때 다음 사용 가능한 번호로 재배치한다.

## GitHub 자동 수집 활성화

운영 서버 환경의 `PLATE_OPERATIONS_GITHUB_TOKEN`이 비어 있으면 수집은 실행되지 않고 화면에 설정 필요가 표시된다. 세 저장소 plateAppServer, plateApp2, plateService의 Actions 읽기 권한만 부여한 서버용 토큰을 설정해야 한다. 토큰을 코드·웹·문서·Git에 넣지 않는다.

고정된 GitHub 주소·허용된 CI/배포 워크플로만 읽는다. 10분마다 저장소별 main 최신 30개 실행을 확인하고, 토큰·실행 로그·제목·사용자 정보 없이 실행 ID·재시도 횟수·SHA·결과·시각만 보관한다. 전용 단일 작업 스레드가 기존 채팅 예약 작업을 막지 않으며 중복 수집을 제한한다. SHA와 저장소가 일치하는 버전에만 결과를 연결한다. 워크플로 성공으로 앱스토어 출시·기기 동작을 자동 판정하지 않는다.

## 검증과 복구 자료

검증 기록과 실제 화면 캡처는 `output/operations-management-2026-10-12/`에 저장한다. 브라우저 캡처의 수치는 명시된 격리 테스트 데이터이며 운영 값이 아니다. 서버의 JWT 권한 검증과 실제 PostgreSQL SQL·동시성·보관기간·롤백 검증은 별도 수행했다.

대용량 node_modules, Maven target/JAR, 임시 PostgreSQL과 Python 환경은 앱 작업 공간 밖의 `/private/tmp`에 두었다. 서버·웹 소스는 Git bundle 및 패치로 작업 공간에 보존한다. 앱 기존 변경은 일괄 커밋하거나 되돌리지 않았다.
